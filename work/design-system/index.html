One system in both directions

When anyone on the co-op’s team edits its website with an AI assistant, a check stops them from breaking its colors, type and spacing. I built that check in summer 2026, on one set of tokens: named values, such as primary for the brand green, that live in the WordPress theme, in its CSS and in Figma, and are checked for drift in both directions.

A decade of CSS had drifted out of any system

The theme’s own audit called it “a decade of drifted, hardcoded, duplicated CSS”: 66 raw font sizes and nine competing page widths. Underneath sat one bug. WordPress silently overrides four font sizes unless a theme opts out, so body text had been rendering at 20px instead of 16–17px.

WordPress’s own variable names became the contract

WordPress already turns theme.json into CSS variables such as --wp--preset--color--primary, so I made those names the contract instead of adding a second vocabulary on top. The editor’s color picker, the CSS, the Figma file and the bakery plugin now use the same strings. The cost: one color name keeps a capital letter, because renaming it would mean migrating saved content.

An AI session can’t hardcode a value without it surfacing

Two pieces guard the tokens when someone edits the theme with Claude Code. A skill, a set of instructions every session loads, tells the assistant to name each token before writing CSS and to list every raw value in its change. A hook, a script that runs by itself after every CSS edit, reports any hardcoded value, with its file and line, back into the conversation.

I tested it cold on four AI models, with bare asks like “try a new orange, something vivid like a tangerine” and “hardcode 13px”. The skill triggered unprompted, its contrast math ruled out white text on the orange, and a planted #ff6600 made the hook fire. The skill does the main work, and the hook is a backstop for anything it misses.

The buttons went through the same math. White on the brand green measured 4.48:1, which “fails AA by 0.02” (AA is the accessibility standard’s minimum of 4.5:1 for text), so the Tertiary fill was darkened from #228848 to #1E7A40.

When Figma and code disagree, a checker fails

Parity means every token has the same name and value in code and in Figma. Before any design session, a Python script compares an export of the Figma variables with theme.json, in both directions. No later run is recorded, because the script needs a fresh Figma export, so code and Figma were in parity when last checked.

Every change goes through the front door

  1. A missing token stops the work.

    Nobody hardcodes “for now”; the session proposes a name, a value and a reason.

  2. theme.json changes first.

    Then Figma, then a dated changelog entry. Adding a token is a minor version; renaming one is major.

  3. A reusable color mix becomes a named token.

    I added this rule on 22 July 2026: a mix left inside one component passed the hook’s check, but no later page could find it. Two days later the events pages’ local neutrals became three named tokens in v1.1.

The bakery plugin waited for the 17 July freeze

The cleanup ran from 25 June to 21 August 2026: 359 commits. On 17 July an overnight agent run froze v1.0, rebuilt the Figma library to match, and shipped the checker, the skill and the hook. The next morning I ratified 13 of its 14 provisional calls and reversed one.

The Figma library is the same system, drawn

The library has three collections and 60 variables, each pointing at its exact CSS variable. The Button is one component set of 7 variants, 3 sizes and 5 states, 105 in all.
