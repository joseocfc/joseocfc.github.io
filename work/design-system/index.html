One system in both directions

The co-op’s website runs on a WordPress theme I designed. In summer 2026 I replaced its drifted CSS with one token contract: written once in theme.json, emitted as CSS variables, mirrored as Figma variables, and checked for drift in both directions before any design work starts.

A decade of CSS had drifted out of any system

The theme carried what its own audit called “a decade of drifted, hardcoded, duplicated CSS”. The front end had 66 raw font-size declarations, z-index values as high as 9999999, and nine competing page widths with no shared token.

One bug sat underneath it all. WordPress core silently overrides four font-size slugs unless a theme opts out, so body text had been rendering at 20 px when it should have been 16–17, and a retune did nothing for four of the six sizes.

WordPress’s own variable names became the contract

I decided against the usual second vocabulary, a --brand-green layer on top of WordPress. WordPress already turns theme.json into variables like --wp--preset--color--primary, so those emitted names are the contract, with “no parallel --cfc-* layer”.

The editor’s color picker, the front-end CSS, the Figma file and the bakery plugin now speak the same strings. The cost is written down too: camelCase keys come out kebab-case, and one slug keeps its capital letter because renaming it would mean migrating saved content.

94 tokens in seven families, and a quarter of them describe one button

The contract holds 94 tokens: 10 brand colors, 6 spacing steps, 6 font sizes, 2 font families and 70 custom keys. Figure 1 sorts them into seven families by what they set. Spacing is a fixed 8 px ladder with a deliberate gap at 12. The palette skips its sixth ordinal on purpose, because filling it would shift the mapping.

Figma modes hold the two ends of every fluid size

Fluid type has no Figma equivalent, so Figma stores only the two ends of each size. The Type collection has two modes: Mobile is each clamp() minimum and Desktop its maximum, so body text reads 16 px in one and 17 in the other, and the largest size 36 and 75.

When Figma and code disagree, a checker fails

Before any design session, a 221-line Python script compares a dump of the Figma variables with theme.json. Every token must exist in Figma or be listed as not mirrored, with a reason. Every Figma variable must map back to a real token, values and alias targets must match, and the five shadow styles must exist.

The allowlist doubles as documentation: 34 tokens are deliberately not variables, such as the z-index ladder (“Figma has no z axis”) and transitions (“no time axis”). All four recorded runs ended in PASS. The last, on 21 August 2026, caught radius/pill drifting from 999 to 99, and the drift was fixed.

The script needs a fresh export of the Figma variables, and no run after that one is recorded. Code and Figma were in parity when last checked on 21 August 2026.

An agent can’t hardcode a value without it surfacing

A project skill tells every Claude session to name each token by slug before writing CSS, and to end with a proof table for every raw value in its diff. A lint script with six rule families runs as a PostToolUse hook after each CSS edit, and exits 2 to put the violation, with file and line, back in the conversation.

I tested it cold on four models, with bare asks like “try a new orange, something vivid like a tangerine” and “hardcode 13px”. The skill triggered unprompted, contrast math ruled out white on orange, and a planted #ff6600 made the hook fire. The skill does the main work, and the hook is a backstop for anything it misses.

This portfolio is held to the same rule

The hook is the lint script that runs after every CSS edit and reports any hardcoded value. In this site’s first review round the agent working on CSS held the portfolio’s own stylesheets to its rule, and hex color literals outside tokens.css went from 108 to 0. The 968 lines of inline <style> CSS on 10 pages went to 0 as well; they now sit in 10 page stylesheets of 869 lines, because a sheet that had been pasted four times is kept once.

Every change goes through the front door, with a version number

  1. A missing token stops the work.

    Nobody hardcodes “for now”; the session proposes a name, a value and a reason.

  2. theme.json changes first.

    Then the token is mirrored to Figma in the same session and gets a dated changelog entry.

  3. Adding is a minor version; renaming is major.

    A rename also needs a migration note, and the bakery plugin’s copy of the contract updated in the same change.

  4. A reusable color mix becomes a named token.

    I added this rule on 22 July. The next section explains why.

I made shared color mixes into tokens; left inside a component, no other page could find them

On 22 July I set a rule for color-mix(): a mix that stands for a reusable design decision gets promoted to a named token in theme.json.

The alternative I rejected: leaving those mixes where they were. A mix built from tokens inside one component already passed the lint.

Why: a mix kept inside one component is invisible to every later page. The lint passes it, and the system leaks anyway.

The result: on 24 July the events library’s local neutrals became surface-mint, line-moss and text-muted in contract v1.1, an additive change with no renames. theme.json changed first.

The bakery plugin waited for the 17 July freeze

The cleanup ran from 25 June to 21 August; 359 commits landed in that window. On 17 July an overnight run froze v1.0 at commit 1a43808, rebuilt the Figma library to match, and shipped the checker, the skill and the hook. The next morning I ratified 13 of its 14 provisional calls and reversed one.

The Figma library is the same system, drawn

The library has three collections and 60 variables, each with its code syntax set to the exact CSS variable. The Button is one component set of 7 variants, 3 sizes and 5 states, 105 in all plus a Loading switch, with its placement rules written on the canvas.

Contrast is computed. White on the brand green measured 4.48:1, which “fails AA by 0.02”, so the Tertiary fill was darkened from #228848 to #1E7A40.

It’s live on communityfood.coop

On 7 November the production site’s markup carried the theme, the Header V2 design, the button variants and 68 custom properties from the contract.

Loose ends, left visible on purpose

Honest state · 7 November 2026

  • The Figma cover still carries its freeze stamp: v1.0 and “PROVISIONAL until Jose ratifies”. I ratified the contract on 18 July, and it has been at v1.1 since 24 July.
  • The changelog was last updated on 21 August 2026. It leaves out the two bakery collections created on 7 August, which only show on the Token Board.
  • Cards and forms are still a placeholder section; of the components, only the buttons are complete.
  • 14 raw hex lines remain in the front-end CSS, and the full lint still reports one violation.
