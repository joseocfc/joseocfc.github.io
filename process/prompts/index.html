ProcessPrompts

One prompt, annotated

Each agent that built this site started from a written prompt; this is the one given to the QA agent that checked every page, trimmed, with a note on what each part is for.

  1. Read … SPEC.md and all lanes/notes. An agent starts with no memory of the build. The prompt names what to read first: the site’s written contract, and the notes earlier agents left behind.
  2. 390, 768 and 1440 in light and dark. Widths and themes are spelled out, so “check it on mobile” can’t shrink to one screenshot.
  3. Read each PNG. Agents will save screenshots they never look at unless the prompt says to open them.
  4. headless Chrome … overflow at 390. Review round 1 found the gap here. A headless window set to 390px does not behave like a phone, and the Epoch study’s false premise came from the same kind of check. The study was re-tested with device emulation.
  5. as a table: issue · page · severity · fixed? · how. The output is a table I can check line by line.
  6. Do not redesign anything. Scope. A QA agent that starts redesigning creates work that needs its own review.
